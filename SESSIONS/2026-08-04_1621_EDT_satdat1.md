## P5 · 2026-08-04 ~16:47 EDT · widen D23, but "I'm guessing most of the projects I use in the future will be ones I created"

**Peter is largely right and the entry now says so.** The loud half of this hazard —
`git mv` refusing a case-only rename — only arises when an existing lowercase folder is
renamed, which is a migration, and the migrations are nearly done. Widening D23 to
cover `mkdir -p` does not change that.

What survives the restructure is narrower than the entry implied: a spine folder can
acquire a lowercase twin from something that is **not** a migration — `sphinx-quickstart`,
a Pages setup, any tool that makes its own `docs/` in a repo that already has `DOCS/`.
On a case-insensitive volume those are one directory and the tool exits 0. Rare, but it
does not expire, which is the only reason the bullet is worth keeping.

**Widened** `claude-config`'s D23 gotcha bullet around the quiet failure rather than the
loud one: `mkdir -p DOCS` in a tree holding `docs/` resolves to the existing directory
and **exits 0**; git's index is case-sensitive so `git status` looks right; **check with
`ls -d`, not `git status`**. Added a second bullet recording Peter's qualification and
attributed to him, so the entry does not oversell itself to a future reader.
